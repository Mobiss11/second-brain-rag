# Архитектура

## Поток

```
knowledge/*.md
   -> нарезка по блокам (---)
   -> эмбеддинги
   -> Qdrant (локально файлом или сервером)
                              ^
вопрос -> эмбеддинг вопроса -> поиск top-k
   -> порог релевантности
        -> ниже порога: ответ "уточню у человека"
        -> выше: контекст + правила -> LLM -> проверка (судья) -> ответ
```

## Почему так

Модель не хранит знания. Её задача - переформулировать найденное. Поэтому база
лежит в файлах, поиск отдельно, а ответ ограничен контекстом. Это защищает от
выдуманных цен, сроков и фактов.

## Решения и параметры

| Что | Как | Почему |
|---|---|---|
| Формат базы | markdown, блоки через `---` | правит человек, читает агент, видно в git |
| Размер блока | 300-800 знаков | крупные куски размывают поиск, мелкие теряют смысл |
| Эмбеддинги | любой OpenAI-совместимый API | провайдер меняется без правки кода |
| Хранилище | Qdrant | локально без сервера, потом сервер для команды |
| Поиск | top-4, косинус | больше 6 кусков модель теряет главное |
| Порог | 0.35 по умолчанию | калибруется на своих вопросах |
| Ответ | temperature 0.2, 700 токенов | точность важнее красоты |
| Судья | второй проход, отключается | ловит цифры не из источника |

## Чего не хватает для продакшена

- Инкрементальной переиндексации по хешу файла.
- Гибрида: полнотекстовый поиск плюс векторы для точных номеров.
- Набора вопросов с эталонными ответами и метрик recall@k.
- Расписания и очереди заданий.
- Интерфейса и каналов.
